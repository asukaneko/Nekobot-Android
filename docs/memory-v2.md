# 单会话角色记忆第二版

本说明适用于单会话角色的融合记忆路径。普通聊天、其他 Agent 记忆和远端会话仍使用各自原有规则。实现采用 Kotlin、Room 和 Compose，界面资源覆盖简体中文、繁体中文、英语、日语和韩语。

## 发送前总结记忆

用户消息先落库，再用同一套Token估算检查尚未总结的完整轮次。默认近期原文预算为8000；达到预算且有旧轮次可处理时，先总结再回复。2000是每批原话的目标量，不是单独的积累触发门槛，也不是生成摘要的长度。8000只限制近期原文，不包含系统提示、记忆与工具等材料。

从最旧未总结整轮起，每批目标约2000；成功完成输出、逐条保存结果，并在事务内核对整批原话指纹及保存完成回执后，这批才退出后续普通聊天的近期输入。例如约8000→总结约2000→剩约6000，随后增长再循环；积压较多时连续处理多批，恢复预算后即停止，不必凑满8000。回执按资料库、会话和角色隔离，重启后继续使用；已总结原话不会再回填近期窗口。聊天、来源和记忆仍留在数据库，可回看或通过明确引用及检索读取。

普通批次尽量保留整轮，最多约4000；单个更长的历史轮次独占一批，绝不为了凑2000拆句或剪掉内容。完整总结请求先减少参考原话及旧记忆，仍超出模型容量时缩小为较少的完整轮次；只有单个完整轮次仍放不下才提示换更大模型。仅实际发送且成功保存的部分记完成回执，转换入口继续处理剩余部分。本轮尚未回复的消息不能提前总结；若它本身超过近期预算，则停止发送并提示调整输入或预算。总提示词容量不足时也必须先成功总结旧轮次，不能静默裁剪未总结原话。

一次连续处理使用现有“正在总结记忆…”状态。网络直连异常、格式错误或不完整结束最多尝试3次，间隔1秒、2秒；已经走完故障转移队列的失败不再整队重复。每批沿用总结用途的10分钟总时限，包含所有尝试和退避，内部模型请求仍受原有超时限制。认证、额度、容量、保存等不可立即恢复的错误直接结束本轮。错误按已知原因给出五语安全提示和重新发送/检查设置等操作，不显示服务原始错误体、地址或凭据。

失败、超时或取消都不写该批完成回执、不继续普通回复，也不跳过失败批次；原话和已逐条保存的有效结果保留，重试按持久操作标识跳过重复操作。再次发送仍从最早未完成整轮处理。状态在结束时清理，用户可再次发起；已完成的前批不会重做。回复结束、手动编辑记忆后不额外触发后台总结。

## 编号、逐条写入与版本

- 每次调用由程序生成本批原话S编号、辅助原话R编号、旧记忆M编号；新增操作按顺序获得N编号。失败的新增操作也占其编号位置，不能把后续编号前移。
- 输出为JSONL，只支持`add`、`update`、`cancel`、`complete`、`retract`，最后必须输出`{"done":true}`。每条通过校验后立即事务入库；坏行不回滚已成功条目。
- 证据仅接受本批S编号，辅助R编号不能作为证据。未知目标不能降级为新增；用户画像必须有用户原话证据。回复中的工具使用同一套写入器，证据限本轮用户S1。
- 发送前总结只有输出完整结束、没有被拒绝的操作，且整批原话指纹仍一致才写完成回执。坏行和未完成输出保留有效写入，但整批重试，已存操作按幂等标识跳过；单个完整轮次不拆。旧资料转换继续使用其原有重试分包策略。
- 更新或撤回将旧版标为作废，保留历史，查询给模型只提供当前有效版本。恢复会建立新的当前版本，历史仍可追溯。

## 拿不准与锁定保护

锁定或人工修改的记忆不能被模型直接覆盖；需要变更时另存一条待确认记忆。待确认内容独立注入上下文，由角色自行决定是否自然询问，不在回复末尾强行追加问题。按用户回合控制休眠与唤醒，重复生成同一用户消息不重复计数。

待确认内容首次被修改确认时，未锁定的原记忆可按规则作废；锁定的原记忆进入待处理队列。聊天在前台、总结和生成结束、回复已落库之后才逐条展示处理弹窗；支持当场编辑、保持原记忆或删除。编辑后继续保持锁定。

## 日期与来源

时间按包含该表达的证据消息说出当天解释，而非总结当天。离线五语词库能解析时以程序日期为准；范围、模糊词、多个日期或不支持的表达返回Unresolved，事件日期留空，不采用模型猜测或把消息发送日期当事件日期。“那年”“上次”等原意、事件内容和来源消息时间继续保留，不因日期缺失丢弃符合筛选的记忆。明确的相对年份加圣诞节、韩语固有数词“이틀 전”等可确定表达按证据日期计算。习惯性表达不强行落到某一天。

记忆页显示完整原消息，原消息删除后显示保留快照和已删除提示。日期按界面语言展示今天、昨天、同年月日或跨年年月日。删除、编辑及编辑后重新生成会一次汇总受影响记忆，默认展示前5条并支持展开；取消不改消息或记忆。提交事务内再次检查确认范围，避免确认后新增关联被静默删改。

## 数据库与便携数据

数据库版本保持64。63→64保留旧数据并增加作废版本、待确认、幂等操作、来源快照和锁定处理队列相关字段与表。新实体通过统一DAO访问。消息变化触发器对融合记忆路径采用新的明确选择语义，其他路径继续保留原保护。

旧库直接升级到记忆第二版时，Room在到达60后选择新增的60→64路径，跳过历史60→61中的物理清理，但保留中间全部结构变更。61、62、63起点仍走各自后续迁移；新版字段建立后，对明确被替代或撤回的未锁定、非冲突记录统一标记历史，保留正文、人工标记、原话出处、向量及关联记录，不把来源失效标记改回有效。锁定与冲突记录继续保留原有保护。

此修复只保护尚未经过旧清理的数据。已经处于64的数据库不会重跑迁移；过去被旧版本物理删除的记忆不能凭新字段自动恢复，需要删除前的备份。迁移回归使用虚构数据和Room实际路径，覆盖53—63起点及人工、自动、锁定、冲突、撤回和来源失效情况；不能代替真实设备升级验收。

便携导入导出包含新字段及相关记忆数据，包括幂等操作和待确认注入计数所需的`companion_applied_ops`；兼容旧归档未包含该表的情况，保持归属隔离和恢复事务。导入操作进度时检查其结果记忆属于同一范围，不允许改绑归属；旧归档中从未保存的操作进度无法凭空恢复。

写入操作的幂等标识纳入来源指纹。消息编辑并选择连带作废后，可以基于新来源重新提取；旧记忆和出处保留，重复尝试仍不重复生成记忆。旧标识兼容检查会验证其来源版本，过期调用不能借旧成功回执跳过来源核对。

转换中因失效、过期或撤回而排除的旧来源保存独立排除标记，不伪装成模型成功总结回执。该标记随转换和便携归档保存，只作用于自动总结及近期原文输入，原话回看和明确检索继续可用。来源实际改变后按新内容版本重新判断；过去转换已经丢失的排除原因不能自动重建。设备上的升级仍应备份并独立验证，JVM迁移测试不代表设备验收。
