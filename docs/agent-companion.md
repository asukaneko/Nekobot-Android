# Agent 角色（长久陪伴）

本地会话的“＋”菜单提供独立创建入口。创建时选择未用于聊天的新角色；一个角色固定一个主窗口。普通角色、普通 Agent、群聊和旧版长久陪伴维持原路径。已有聊天不会自动转换。进入、退出或迁移已有角色，需要备份后由外部 Agent 协助转换。

## 数据与记忆

数据库从 50 增量升级到 51。`local_sessions.companion_mode` 默认关闭；`companion_owners` 和数据库触发器共同约束窗口归属、绑定和模式修改。删除窗口意味着清空这个窗口的记忆与历史：作用域内的记忆、来源、回执、检索向量一并删除，归属同时释放（旧库中指不到窗口的悬空归属会在读取时清理），角色重新开始并可再建唯一窗口；完整备份仍可还原原窗口。

新模式只使用当前窗口的 companion 存储作为长期事实库，分类为用户画像、角色画像、双方关系、共同经历、约定、未解决事项。复用来源、版本、事务回执、待确认和向量索引。管理页提供搜索、分类、标签、编辑、删除、版本和聊天原文定位。

- **每次聊天都提供**控制常驻注入，显示估算 Token；超过预算明确报错。
- **只允许我修改**保护条目不被自动改写，玩家仍能修改或删除。这两个设置互相独立。
- 公共 Agent 长期记忆不注入、不整理；记忆工具及子任务路由到此窗口。文件工具保持工作区边界，新模式的 Linux 命令环境不挂载宿主 `/proc`。
- 数据导出中心包含模式、归属、记忆、来源和整理进度。单独聊天 JSON 不承载完整记忆，因此不允许将新模式作为普通聊天 JSON 导入。请求辅助资料是可重建缓存。

## 整理与发送

后台按未处理旧段的 Token 量触发，只在完整回复结束后处理。一次请求包含目标旧段、近期参考原话和相关旧记忆。只处理目标段；参考段不提前入库。模型在同一次调用中提取画像、延续事件、处理纠错与矛盾，不额外调用判断或重排模型。

成功提交记忆与处理回执后才推进进度。无效 JSON、越界来源、源消息变化或容量不足均拒绝提交，保留原话和待处理位置。进行中的事件继续更新同一 key；重复事实合并来源。删除不倒退游标，后续新的明确表达仍可记录。

默认预算：近期完整原话约 8000 Token，常驻约 1000，召回约 2000；旧段约 2000 触发，单批约 2000～4000。扣除系统、工具和输出预留后缩减，小聊天模型的保留窗口也约束整理参考段。完整回合超限时明确失败，不截断后假装成功。

关键词与缓存向量共同召回；文档向量后台增量建立，查询最多等待 1.5 秒，失败回退关键词。保留原有 4096、自定义、接口默认维度配置及免费模型提示。

基础提示和工具顺序保持稳定；日期/时段、召回结果及其他动态资料追加到当前轮辅助资料，明确软件来源。发送过的辅助资料在预算内保留，达到边界成批重建；修改、删除和权限变化使旧缓存失效。资料不写回聊天消息表、不再次提取。精准时间仍使用 `get_date_time`。服务商不报告缓存时显示未提供，不当作 0 命中。

新模式不使用覆盖式近期摘要或滚动历史总摘要；手动压缩入口隐藏，动作层拒绝调用。普通模式仍保留这些功能。

## 验证入口

- `FusedCompanionPolicyTest`、`CacheReportingAvailabilityTest`：预算、完整回合、工具定义、缓存字段语义。
- `FusedCompanionAndroidTest`：归属、事务边界、失败重启、参考段、事件/纠错/冲突、常驻保护、删除、向量超时、请求前缀。
- `CompanionMigrationAndroidTest`、`PortableDataArchiveManagerTest`：旧库升级与完整归档恢复。
- `FusedCompanionMemoryScreenTest`：管理页操作。
- `FusedCompanionLiveAndroidTest`：默认跳过。显式配置仅回环测试桥后，用合成对话请求实际服务商；密钥留在主机内存，不进入 App 或测试仓库。

模拟器测试不代表真机验收；模拟向量测试不代表真实嵌入服务质量；相同请求前缀不等于服务商缓存命中。个人构建使用仓库外既有脚本与固定签名，不在源码中保存个人构建秘密。
